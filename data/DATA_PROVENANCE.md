# Data provenance

The pipeline now runs on **real OpenCelliD data**. A representative (synthetic) set is also
kept for reference and offline regeneration.

## `watthana_cells_real.csv` — ACTIVE (real)

**Real OpenCelliD extract.** Fetched with `scripts/download_opencellid.py` via the OpenCelliD
`getInArea` API, filtered to Thailand (MCC 520), True-group MNCs `{0,4,5,18,25,99}`, and the
Watthana / Sukhumvit bounding box (lat 13.710–13.752, lon 100.550–100.600).

- These are **crowdsourced estimated positions**, NOT surveyed tower locations — exactly as the
  deck states.
- Only **LTE/UMTS** are treated as sleep candidates; **GSM is excluded** — it stays awake as the
  2G coverage floor, so sleeping broadband never drops a user to 2G speeds. (No NR — OpenCelliD's
  crowdsourced 5G coverage of this area is sparse.)
- ~3,401 True-group LTE/UMTS cells → ~851 sites → **116 atoms** after merging within the 238 m
  (= 4 µm) Aquila floor. The headline sub-district is the densest ~90 that fit the 75 µm field.

To refresh it: put your token in `.env` as `OPEN_CELLID_TOKEN=...` (the `.env` file is
gitignored — never commit it) and run `python scripts/download_opencellid.py`.

## `watthana_cells.csv` — reference (representative / synthetic)

Generated by `scripts/generate_representative_data.py` on the real Watthana geography (real
bounding box, Sukhumvit BTS corridor, real True/dtac MNC codes) but with **synthetic positions**
— not real records. Kept so the demo can run with no token, and as a calibration reference.
Point `DATA_CSV` back at it to use the representative set.
